## 1. 定位（M1 · 源码交付 + 代部署）

- **卖什么**：一份源码 + 一次代上传部署。客户交钱后，你改 `brand.config.ts`（店名/logo/微信/电话）并帮他传到**他自己的**微信小程序账号；后端用**客户自备的 CloudBase** 环境。
- **为什么是 M1 不是 SaaS**：目标是快钱。M1 不托管、不续费、交付即结束，且贴合"不办个体户/不暴露个人信息"原则（客户自己注册小程序主体）。SaaS（多租户年费）是长期生意，被否决。
- **终端用户 = 花店顾客（C 端）**；产品归属花店，不是平台。
- **老板 = 非技术花店主**：他不碰代码、不碰部署——部署由你代劳（收费）。
- **收款走淘宝/闲鱼代收线索，不经微信支付**（既定策略）。

## 5. M1 技术实现

- **品牌本地化**：`miniprogram/utils/brand.config.ts` 是唯一品牌来源；`brand.ts` 的 `getLocalBrand()` 直接读它，无云端请求、无 `shops` 集合（已删除 `get-shop`/`save-shop` 云动作）。
- **前端参数化**：首页品牌字、导航栏标题、`home-bg` 大图、`work-image-empty`、底部导航 aria-label 全部读 `brand`。
- **角色门控**：`isAdmin`（老板 openid 白名单）控制创作入口与"灵感"tab 显隐；顾客首页展示品牌 hero + 精选作品。
- **隐式登录**：进入即 `bootstrapBackend()` 拿 openid，不弹授权、不接废弃 `getUserProfile`。
- **后端归属**：交付时把 `miniprogram/utils/cloud-env.ts` 的 `CLOUDBASE_ENV_ID` 改成客户的 CloudBase 环境 ID；客户自备云开发环境，你不在后端托管任何人。

## 8. 代部署 SOP（你交付时的操作清单）

1. 客户付款，收其微信小程序 **AppID** + 已认证的**小程序账号**（企业 300/年，个人免认证但类目受限）。
2. 改 `miniprogram/utils/brand.config.ts`：店名/logo/微信/电话/标语/简介。
3. 改 `miniprogram/utils/cloud-env.ts` 的 `CLOUDBASE_ENV_ID` 为客户自己的云开发环境（指导客户开通云开发）。
4. 微信开发者工具导入代码 → 填 AppID → 上传 → 提审 → 过审发布。
5. 把老板微信号 openid 加进云函数 `adminOpenIds()` 白名单并部署（否则老板看不到创作入口）。
6. 交付：客户自己运营，你不再托管。后续 bug 修复按需单收费或卖升级包。
