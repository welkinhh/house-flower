# B 端花店白标小程序 · 重新规划（分支 `b2b-whitelabel`）

> 目标：把现有"House花生"个人花艺小程序，重构为**可换 logo 的 B 端花店小程序**，
> 让非技术花店老板登录即用、各自挂品牌，用来展示作品集并获客。
> 本分支已完成第一步：删除花历与重要日子，仅保留作品集（commit `5a9f49e`）。

---

## 1. 定位

- **单实例多租户 SaaS**：一套代码 + 一套云端后端，N 家花店各自换 logo / 店名 / 主题色，数据按 `ownerId`/`shopId` 隔离（沿用现有 cloud 后端隔离能力）。
- **终端用户 = 花店的顾客（C 端）**，产品归属花店，不是平台。
- **老板 = 非技术花店主**，登录即用，不碰代码、不碰 config、不办个体户（与既定策略一致）。
- **收款走淘宝/闲鱼代收线索，不经微信支付**（既定 B 端策略，避开微信支付资质与提现麻烦）。

---

## 2. 与现状的差异

| 项 | 现状（master） | 本分支后 | B 端目标 |
|---|---|---|---|
| 花历 / 重要日子 | 有 | **已删除** | 不需要（或被"节日/促销"模块替代） |
| 作品集 | "我的作品" | 仅保留 | 重定位为**店铺作品门面** |
| 品牌 | 硬编码 House花生 | 硬编码 | 参数化为**每店品牌配置** |
| 创作 AI | 拾光成花/识花成单/花映生活 | 保留 | 待决策（见 D1） |
| 多租户 | 单用户 | 单用户 | 按店隔离 + 开店 |

---

## 3. 如何展示（UX）

- **店铺品牌页（替代原"首页/我的"）**：顶部店铺 logo + 店名 + 一句话简介 + 联系入口；下方精选作品轮播/网格。
- **作品集（核心，已保留）**：网格展示花束 / 场景 / 清单；分类筛选（婚礼 / 生日 / 探病 / 商务 / 节日 / 当季）；点开大图详情（图 + 花材清单 + 可收藏 / 分享 / 咨询）。
- **底部导航（精简）**：`首页(品牌)` / `作品` / `关于(联系)`。原"灵感""创作"在 MVP 视决策保留或移除。
- **白标换肤**：logo、店名、主题色（强调色）随店铺配置生效；默认沿用现有米杏色调，老板可改主色。

---

## 4. 功能清单（分阶段交付）

**Phase 1 · 品牌白标 + 作品门面（MVP 可交付）**
- 品牌配置：logo、店名、主题色、简介、联系方式（微信/电话）。
- 作品集展示 + 分类筛选 + 详情（大图 / 清单 / 分享 / 收藏）。
- 分享到微信好友 / 朋友圈（带店铺 logo 的卡片）。

**Phase 2 · 老板管理后台**
- 上传作品（图 + 标题 + 分类 + 清单）、排序、上下架。
- 数据看板：浏览 / 收藏 / 咨询量。

**Phase 3 · 客户互动**
- 收藏、一键微信联系 / 留资（不走支付）。
- 节日 / 促销模块（替代已删"重要日子"的需求）。

**Phase 4 · 多租户开店**
- `shopId` 开通、按店隔离、店铺码 / 二维码分发、淘宝/闲鱼代收线索回传。

---

## 5. 白标实现方案（技术）

- **新增 brand 配置（云端 per shop）**：`{ shopName, logoAssetId, themeColor, intro, contact }`。
- **前端参数化**：`app.json` 标题、`DEFAULT_PROFILE`、各页 `topCaption`、header 头像 全部读取 brand；强调色把散落的 `#bd7d7d` 收敛为 CSS 变量 `--brand` 注入（分阶段做，见 D3）。
- **多租户**：现有 cloud 已按 `ownerId` 隔离；加 `shop` 实体，顾客端按 `shopId` 浏览。
- **推荐：配置化白标（单实例）**，不要每个店建分支 / 单独构建——否则 100 家无法维护。

---

## 6. 收费模型（建议，沿用既定 ~100 家 × ¥800）

- **基础年付 ¥800 / 店 / 年**（≈¥67 / 月）：含白标、作品集、分享、基础数据看板。
- **月付 ¥99 / 店**：灵活，但年付更稳、转化更好。
- **免费试用 14 天**，到期转付费或降为"带平台水印"的免费档。
- **增值项**：高级模板 / 更多作品位 / 节日营销包，单买 ¥100–300。
- **收款**：淘宝 / 闲鱼代收，不经微信支付（与既定策略一致，规避支付资质）。

---

## 7. 关键决策（已确认 · 2026-10-07）

- **D1 · AI 创作**：转"老板辅助创作"。拾光成花 / 识花成单 / 花映生活 从顾客前台移入"老板模式"，顾客端看不到生成入口。
- **D2 · 顾客登录**：必须微信登录。进入即授权，用于收藏 / 留资 / 身份。
- **D3 · 换肤范围**：MVP 仅 logo + 店名 + 简介，强调色暂沿用米杏默认；主题色变量化放后续。
- **D4 · 下单支付**：MVP 仅咨询留资，成交走淘宝/闲鱼代收，不经微信支付（与既定策略一致）。

## 8. Phase 1 实施清单（已确认开工）

1. **品牌配置层**：新增 per-shop `brand`（云端 `shops` 集合，`shopId` 默认 `default`），字段 `shopName / logoAssetId / intro / contactWechat / contactPhone / slogan`，本地 + 云端读取，离线回退默认品牌；MVP 先支持单店配置，多租户 `shopId` 路由留 Phase 4。
2. **前端参数化**：消除硬编码 `House花生` / `花生用户`；首页品牌字、导航栏标题、`home-bg` 大图、`work-image-empty`、底部导航 aria-label 改读 brand；默认头像保留为顾客资料，不做品牌强制替换。
3. **角色与登录（隐式）**：进入即 `bootstrapBackend()` 建会话（openid 即身份），不弹授权页、不接已废弃 `getUserProfile`；收藏 / 留资等需身份的动作 gate 在 `backendReady`。老板 = `isAdmin`（openid 白名单），顾客 = 非 admin。
4. **作品集门面**：保留的作品集作为店铺门面；顾客首页展示品牌 hero + 精选作品；详情加"联系老板"入口（微信 / 电话，来自 brand.contact，复制 / 拨打按钮，零后端），无支付、无留资表单。
5. **AI 转老板辅助**：`HOME_ENTRIES`（拾光成花 / 识花成单 / 花映生活）与"灵感"底部 tab 仅对 `isAdmin` 可见；顾客端隐藏，老板创作产出照常进作品集。
6. **老板品牌设置**：`isAdmin` 在"设置"页可见"品牌设置"，编辑店名 / 简介 / 微信 / 电话 / slogan、上传 logo，调 `save-shop` 写回 `shops` 集合（证明白标闭环，多租户后台留 Phase 2/4）。
7. 自测（tsc 零错误）+ 提交分支，交付验收。

> 按 1→7 实施；Phase 2-4 仍按原计划分阶段推进、每段验收。

## 9. Phase 1 技术决策（已确认 · 2026-10-07）

- **D5 · 品牌存放**：云端 `shops` 集合 + 老板(isAdmin)自助改；否决本地 `brand.config.ts`（违反单实例、老板不碰代码）。
- **D6 · 登录方式**：隐式登录（`bootstrapBackend` 自动拿 openid），不打断、不弹授权页、不接已废弃 `getUserProfile`（昵称走现有资料编辑）。
- **D7 · 留资入口**：作品详情仅"联系方式按钮"（复制微信 / 拨打电话，零后端），不做留资表单 / `leads` 集合（MVP 最薄，成交走淘宝 / 闲鱼）。
- **D8 · 老板模式**：复用现有 `isAdmin`（老板 openid）控制创作三入口与"灵感"tab 显隐，不做独立模式开关。
