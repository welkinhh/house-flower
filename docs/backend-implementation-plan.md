## 1. 目标与当前项目基线

本计划依据当前代码，不沿用已停用的花束自由编辑器方案。首版目标：用户能以微信身份使用拾光成花、识花成笺、花映生活，并跨设备访问作品、花材清单、花历和重要日子；AI 任务可恢复、额度可控、异常可追溯。

本地检查确认：

- 当前名称为 House花生，页面入口为 `miniprogram/pages/flower/index`。
- AI 统一由 `cloudfunctions/flowerTaskWorker` 通过 `@cloudbase/node-sdk` 调用，旧的同步兼容云函数已从部署配置中移除。
- `houseflower-data.ts` 中作品、资料、重要日子和次数依赖本机存储。默认次数为 10。
- `creation-actions.ts` 由客户端扣次数；生图、识花失败后存在演示结果分支。文档与当前代码在这点上不一致，以代码为准。

- 当前场景流程是在客户端先合成图片，再调用图生图；普通带背景花束的精准抠图尚不能视为已实现。

- 当前首批后端改动已将 `project.config.json` 的 `cloudfunctionRoot` 指向 `cloudfunctions/`；实际部署方式仍需在微信开发者工具或 CloudBase CLI 中选定。

原则：保留已完成的前端视觉，改造数据访问层、任务交互与必要异常状态；不重新设计页面。

## 2. 技术选型

| 层次 | 首版方案 | 目的 |
| --- | --- | --- |
| 小程序 | 保留原生 TypeScript，增加 service/repository 层 | 页面不直接承担云端协议与存储同步 |
| 身份入口 | 微信小程序原生云开发身份上下文 | 不维护账号密码和自建登录 token |
| 后端业务 | CloudBase 云函数，TypeScript 编译为部署运行时兼容的 JavaScript | 用户、作品、任务、额度、配置等业务 |
| 数据库 | CloudBase 文档数据库，服务端事务及索引 | 适合现有作品和任务文档；事务控制并发扣减 |
| 文件存储 | CloudBase 云存储 | 原图、生成图、缩略图、清单导出 |
| AI | 服务端 CloudBase AI SDK + 统一模型适配层 | 优先使用成长计划对应通道 |
| 异步任务 | 持久任务集合 + 环境支持的可靠异步执行机制 + 定时补偿 | 退出页面也不丢任务 |
| 运维 | 平台日志、告警、基础运营工具 | 查故障、查用量、关闭异常功能 |
| 输入校验 | 共享 TypeScript 类型 + Zod 或等价运行时校验 | 防止前端参数和模型输出破坏数据 |
| 图片处理 | 按部署环境验证的 Sharp 或等价服务 | 缩略图、尺寸检查、EXIF 清理、场景合成 |

使用平台当前支持的稳定 Node.js 运行时，并锁定已联调通过的 SDK 版本。SDK 版本与运行时兼容性在 P0 验证，不盲目升级全部依赖。

首版不引入 Kubernetes、微服务集群、向量数据库、自训练模型或自建 GPU。只有需要稳定长任务执行时，才为 AI worker 引入云托管；其余业务仍使用云函数。

## 4. 用户账号与访问控制

### 身份流程

浏览首页、示例与灵感内容可不建立个人业务账号。用户首次执行保存、同步、AI 上传或个人资料操作时，通过小程序云调用进入身份初始化接口。

云端在经过验证的小程序调用上下文中取得 APPID、OPENID，映射到内部 userId。身份表以 `(appId, openId)` 唯一约束，不信任请求体中的 userId/openId。UNIONID 如可获得可保留，首版不以它为登录必要条件。

用户资料包括：userId、昵称、头像 assetId、状态、创建时间、最近访问时间。头像和昵称由用户主动填写；首版不强制手机号，也不要求密码。

身份上下文用于小程序专用入口。后台、定时任务、worker 和潜在 HTTP 入口分离，不能把定时任务运行时残留身份或任意传入 openid 当作用户认证。

### 权限原则

- 公开内容：仅发布状态可读，只有管理员可改。
- 私有作品、清单、重要日子、文件：所有者可访问。
- 额度、任务状态、模型配置、用量账本：仅服务端写。
- 客户端数据库规则与服务端每个接口的 owner 校验同时存在；云函数使用管理权限不代表可以省略业务鉴权。
- worker 仅接受受信任内部触发，不向小程序开放任意模型执行入口。
- 管理员使用单独可信认证和权限白名单；前端传入 role=admin 不生效。

### 账号删除与设备缓存

账号删除先冻结新任务和写入，再撤销分享、取消待处理任务、清理私有记录及无其他引用的文件。已运行任务终止受供应商能力限制，结果不得重新恢复被删除的账号数据。必要审计记录按明确保留策略最小化处理。

本地缓存按 userId 分区；身份变化清理上一身份缓存。注销、重新进入不能重复领取新手额度。

## 5. 文件与图片资产

文件必须登记在 assets 集合，以 assetId 作为业务接口参数，fileID 为内部存储引用。不要用临时 URL 或本机 wxfile 路径作为跨设备主键。

上传链路：

1. 客户端请求创建上传凭证，声明业务用途和基础文件信息。
2. 云端确认身份、文件数量/容量限制，创建 pending 的 asset 记录及精确存储路径。
3. 客户端直传云存储，避免把大图片经过业务 JSON 接口转发。
4. 客户端确认上传；云端核对精确路径、环境/桶、归属、真实文件类型、大小、像素尺寸和解码结果。
5. 按用途清除 EXIF 等无关元数据，生成缩略图，执行内容检查；通过后设为 ready。
6. AI 创建任务只接受 ready 且属于当前用户或已发布公共内容的 assetId。

源图、场景照片、头像、生成结果默认私有。官方场景和公开灵感图片单独管理。临时访问 URL 按需生成，到期刷新，不作为永久作品地址。

模型输出及时转存到自有云存储。下载外部输出时校验来源域名、协议、重定向、内容类型和大小；不把 HTTPS 本身当作可信来源，不开放任意 URL 下载代理。

保留策略：未完成上传 24 小时清理；任务完成后 24 小时内可恢复并保存；逾期清理未保存任务及其输入、场景垫图和生成结果。作品引用、头像引用及其他未过期任务引用优先保留，不能只按文件年龄删除。没有任务/作品/头像引用的其他临时资源在 7 天后清理。

## 6. AI 接入与效果验证

### 接入原则

优先延续 CloudBase 成长计划的服务端 SDK 通道。现有 HTTP 网关 URL 不等于必须使用 HTTP 接入；Publishable Key 也不是所有模型通道都可使用的通用凭证。

需要管理员 API Key 的能力，仅在云端受保护配置中使用。不给小程序或日志下发密钥。模型名称、提示词模板、尺寸和次数限制由后端配置，客户端只提交业务选项。

账号内 10 万张资源是否到账、有效期、支持模型、图生图是否计入、失败如何计费和识花是否另计必须实测确认。公开活动说明不能代替该账号的资源记录。

### A. 拾光成花

输入：灵感图片 assetId、经过枚举约束的风格选项、可选简短描述。

处理：校验与审核 → 后端拼装版本化提示词 → 图生图生成 → 输出审核 → 转存原图与缩略图 → 建立生成结果记录。

输出：resultAssetId、thumbnailAssetId、taskId、模型与模板版本。暂不自动编造花材清单；需要时用户单独发起识花。

候选模型保留现有 `HY-Image-v3.0-I2I-ToB-v1.0.1`，以账号实测决定是否启用。只有效果确有提升时再增加“视觉理解→结构化方案→生图”的第二次调用，避免不必要延时与成本。

### B. 识花成笺

输入：用户花束照片或自己的生成作品 assetId。

图片理解与图片生成是不同能力。现有 `hunyuan-custom / hunyuan-vision` 需独立验证服务端配置、权限与计费；不能因为生图成功就视为识花也已打通。如果活动通道无混元视觉能力，先提供可用模型和成本评估，再确定备选，不静默调用另一个付费通道。

结果字段：花材名称、颜色、可见数量下限/上限、单位、判断说明、是否需确认、可选标准素材 ID。用户确认值单独保存，原始 AI 估算不可被覆盖。

对模型结果执行 JSON Schema 校验、条目数量限制、范围校验、同义词映射。无法确认时保留未知，不强配素材、不把模型自报置信度当作经过校准的准确率。

少量人工标注样本评估名称匹配、数量区间覆盖、非花束图片处理与遮挡情况。照片无法推断隐藏花材的精确总数。

### C. 花映生活

输入：花束 assetId、场景 assetId、归一化摆放位置和缩放信息。

当前单参考图模型路径：校验两份资源 → 合成一张参考图 → 图生图融合 → 检查花束和空间保持程度 → 保存结果与原始摆放参数。

场景图与花束图分别作为已登记私有资源上传，由 `flowerBackend.compose-scene-reference` 校验素材归属，并使用 Sharp 按画布比例、位置和缩放合成一张私有参考图，再交给图生图任务。该函数及 Sharp 依赖已于 2026-10-01 部署到目标 CloudBase 环境；真实微信身份下的场景合成效果仍需实测。识别到普通照片带矩形背景时，单独评估抠图服务或使用用户确认后的参考图；仅在提示词中要求“去背景”，不等于可靠的主体分割。

花束形态保持、场景结构保持、接触阴影和边缘是质量验收项。不承诺图生图一定保持每一枝花不变。

### 模型适配层

统一提供 generateBouquet、recognizeFlowers、blendScene 三个业务方法，记录 modelId、provider、promptVersion、requestId、耗时、成本状态。结果中明确 provenance=generated/recognized/demo。演示模式仅在开发环境显式开启，不自动把失败伪装为成功，也不计入真实用户用量或作品统计。

## 7. 异步任务与恢复

客户端提交后立即取得 taskId，显示真实阶段并查询状态。客户端关闭、切后台、网络断开不应终止服务端任务。

状态：queued → checking → running → saving → succeeded；分支为 failed、blocked、cancelled、reconciling。

- queued：已持久化，等待执行。
- checking：校验/内容检查。
- running：已调用模型。
- saving：转存输出、生成缩略图。
- reconciling：供应商是否已执行或计费暂不确定，等待核对。
- succeeded：输出可用、结果落库且用户额度结算成功。

不显示虚构的 37%、82% 等生成百分比；使用阶段提示。

执行机制在 P0 选定：优先平台真实支持的异步执行或受保护消息消费；如当前云函数机制不能满足可靠执行，使用受保护云托管 worker 消费持久任务。定时器用于补偿扫描、清理与对账，不将分钟级扫描宣传为即时调度。

禁止云函数返回后依赖未等待的 Promise 继续工作；禁止由前端负责调用 worker；禁止把面向用户的云函数与内部 worker 混用身份上下文。

必备机制：

1. 用户 + 幂等键唯一，同键同输入返回同一任务，同键不同输入报冲突。
2. 任务创建与额度预占事务提交；投递失败仍可由持久任务记录恢复。
3. worker 通过原子条件领取任务，使用租约、心跳和领取版本避免并发执行。
4. 超过租约不直接重新生图，先判断前一次是否已调用模型；不明状态转 reconciling。
5. 输出转存失败仅重试转存，不能重新生成一张图。
6. 数据库结果和用户扣费可幂等重放；外部供应商不支持幂等时，不承诺绝对只调用一次。
7. 客户端查询逐步退避，回到前台查询未完成任务；只允许查看自己的任务。
8. 取消排队任务释放预占；运行中仅记录取消意愿，不能保证供应商立即停止或不计费。
9. 严重失败任务保留 requestId、阶段、错误分类，后台能定位。

## 8. 额度与成本控制

将“用户可用次数”和“腾讯资源包剩余量”分开维护。

用户额度：服务端可用、已预占、已使用。账本记录 grant、reserve、commit、release、adjust。每次变化关联 taskId/活动编号与幂等键。

初期沿用每位新用户 10 次体验作为可配置产品假设，先测单次成本，再确定生图、识花、融合分别消耗多少点数。不要让识花成本与生图成本被一个无依据的数字掩盖。

流程：提交时预占 → 可交付结果成功时结算 → 确认失败按产品规则返还。供应商已计费但用户未收到可用结果的成本单独记录，可由产品承担；不能把用户退款等同于腾讯退款。

客户端本地计数只展示服务端结果，不能修改权威余额；不导入旧本地 remainingUses 作为新余额。新手赠送依据唯一领取记录，换手机、清缓存不重复领取。

项目级限制：每用户并发、用户日上限、全局并发、全局日预算、单图尺寸、最大重试次数和模型开关。建议内测先每用户仅允许 1 个运行任务，全局并发按账号真实配额设置。

到达预算或供应商额度下限后暂停新任务；预留正在执行任务的最大可能成本。供应商若无实时余额接口，后台展示“本地估计 + 最近核对时间”，不标为实时官方余额。

成本构成：云环境/函数或 worker、数据库、存储、图片下载流量、内容审核、抠图、AI 生图与视觉 token。免费生图资源不等于这些全部免费。

预算计算：日任务量 × 各任务平均成本 + 失败/重试成本 + 固定环境成本 + 存储与流量。用真实内测样本估算，当前不虚构固定月费。

| session | bootstrap、getProfile、updateProfile、requestDeletion | 服务端解析身份，返回内部 userId 与本人资料 |
| assets | prepareUpload、completeUpload、getAccessUrls | 精确对象归属、用途、状态和容量检查 |
| works | createFromTask、list、get、rename、delete | owner 约束、游标分页、expectedRevision；原结果与用户保存状态分开 |
| recognition | get、updateConfirmedItems、createExport | 保留原始估算；确认值带 revision |
| tasks | create、get、listActive、requestCancel | 幂等、额度预占、私有任务访问 |
| quota | getBalance、getUsage | 客户端只读，不提供任意加次数接口 |
| calendar | getMonth | 限制查询跨度，返回作品与重要日子 |
| dates | create、update、delete | 日期校验、版本冲突、所属作品校验 |
| content | getHome、listInspirations、listScenes、getPublicConfig | 仅发布内容，支持版本缓存 |
| migration | importBatch、getMigrationStatus | 每用户+设备迁移批次+本地记录 ID 去重 |
| admin | publishContent、inspectTask、adjustQuota、setFeatureFlag | 独立管理身份、操作审计 |

统一响应含 requestId、data 或结构化 error。错误分类至少包括 AUTH_REQUIRED、FORBIDDEN、INVALID_INPUT、QUOTA_EXCEEDED、RATE_LIMITED、VERSION_CONFLICT、MODEL_UNAVAILABLE、CONTENT_REJECTED、TASK_PENDING、RESULT_PENDING_RECONCILIATION。

所有列表限制 pageSize 并使用稳定游标排序。更新接口使用 expectedRevision；冲突返回最新版本供用户处理，不能无提示覆盖另一设备的改动。

## 11. 作品、清单与本地迁移

AI 完成时先持久化结果记录；用户点击“保存作品”才进入已保存作品集。这样既防止关闭页面丢失结果，也保留前端现有保存语义。未保存结果有明确保留期与到期提示。

清单首版可以保留本地图片导出，云端存结构化清单及版本。保存到相册成功后再记录导出事件，不能把点击下载等同于已成功下载。

首次云端同步迁移流程：

1. 识别当前账号并显示本机作品可同步状态。
2. 排除 demo-* 和明确演示来源记录，不将演示图计入真实生成作品。
3. 分批上传可读取的本地持久文件，登记资源后再导入作品。
4. 已有 fileID 也必须校验环境、存在性和归属，不能直接信任历史客户端记录。
5. 上传成功才提交云端记录；记录失败可继续重试，不先删除本机数据。
6. 同时迁移重要日子和用户主动填写的资料，按批次记录进度。
7. 路径失效的图片明确标为待补充，不伪造同步成功。
8. 云端 revision 与本地 dirty 状态用于后续增量同步。

默认不自动上传所有设备内的历史照片；仅同步用户选择保存的作品及必要资源，并在迁移入口说明范围。

## 12. 重要日子、通知与运营支持

首版完成重要日子的增删改查与跨设备花历，包含公历年度重复、作品关联和用户备注。

提醒在第二阶段启用：用户主动订阅 → 保存授权及模板用途 → 生成待发送任务 → 到期发送 → 记录结果与去重键。不把一次授权当成无限次提醒。实际可用模板、授权次数及发送条件在接入时核实；未授权时保留应用内提示，不承诺微信主动推送。

首版管理能力可用受保护的轻量管理页或管理脚本，不必先做大型后台。但至少支持：

- 查任务阶段、错误分类、供应商 requestId。

- 有审计记录的手动补偿额度。

- 用户反馈关联任务，不默认向运营人员展示全部私有原图。

## 13. 安全、可观测性与发布

图片上传、AI 输入与输出、公有素材发布设置必要的内容检查。具体审核通道以账号能力和成本选择；模型拒绝机制不能代替应用自己的发布检查。

数据库、云存储分别配置私有权限。后端强制身份/归属检查、参数白名单、上传限额、用户与全局限流、模型白名单。不要允许客户端自由填写 provider、模型地址、任意回调 URL 或完整系统提示词。

日志记录 requestId、taskId、脱敏用户标识、阶段、模型、耗时和错误分类；不记录完整私有图片、图片 Base64、带签名的长期日志 URL 或密钥。

监控至少包括：任务成功率、P50/P95 时延、排队长度、长时间预占、结果转存失败、模型额度不足、数据库错误、日预算消耗。告警能指向可查询的任务和处理手册。

开发与生产环境隔离；若免费资源只覆盖一个环境，其他环境使用 mock 和小规模受控联调，不混入用户生产数据。配置和 schema 使用版本管理。部署具备回滚步骤，新增字段先兼容旧前端，再切新协议。

备份与恢复：确认套餐可用备份/导出能力，制定数据库与关键资源恢复流程，实际做一次恢复演练。上线前核实微信侧隐私说明、服务类目、AI 内容展示/导出标识及相关平台要求，不把此计划当成已经通过平台审核。

## 15. 必须执行的测试

1. 身份：伪造 owner、跨账号读取/修改/删除、直接调用 worker、普通用户调用管理操作均被拒绝。
2. 文件：伪造 fileID、跨环境对象、类型伪装、超大像素图片、未确认上传都不能进入 AI。
3. 并发：仅余一次额度时同时提交两个不同任务，至多一个成功预占；同幂等键只建一个任务。
4. 崩溃：模型调用前、调用后、输出转存后、最终事务前分别中断，能够安全恢复或进入待核对状态。
5. 计费：释放预占与结算各只能执行一次；未知供应商结果不能自动重生多张图。
6. 数据：双设备重命名冲突、删除与任务完成竞争、重复迁移、图片丢失均有明确结果。
7. AI 效果：建议各准备至少 10 张灵感图、20 张识花图、10 个场景组合，保留人工判断和版本记录；不能用少量样本宣称通用准确率。
8. 真机：后台切换、断网、慢网、取消上传、相册拒绝、临时 URL 到期、重启及换设备。
9. 演示隔离：生产失败不能跳出演示“成功”，演示作品不能消耗额度或自动迁入真实云作品。
10. 发布：模型开关、预算熔断、告警触发、备份恢复和旧版前端兼容性。
