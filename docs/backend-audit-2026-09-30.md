## 验证边界

npm run backend:test通过，但实际只检查次数纯函数、跨北京时间午夜计算和部署配置；没有访问云数据库、云存储、模型或订阅消息。npm run build通过只证明前端结构及类型。微信预览码成功不代表云函数已部署。

剩余验收需要在微信开发者工具/手机端使用真实微信身份跑一次相册上传与作品保存，并单独检查场景融合。识花需用户另行批准一个有计价的视觉模型或配置自有模型；当前开关保持关闭，不会误调用付费服务。

## 2026-10-01 云端验证

- `flowerBackend`、`flowerTaskWorker`、`houseflowerMaintenance`、`houseflowerNotification` 均已部署为 Active；worker 每分钟触发器已恢复。
- 13 个 NoSQL 集合已创建并设为 ADMINONLY；云存储规则只允许登录用户向 `users/<openid>/...` 本人目录上传，禁止客户端直读。客户端联调发现 CloudBase 从路径第二段解析 `resource.openid`，已将上传路径调整为 `users/<openid>/houseflower/private/...`。桶级大小条件导致新文件持续被拒绝，已按用户授权移除；小程序上传前与 `flowerBackend.complete-upload` 服务端仍校验 10 MB 并删除超限对象。直接绕过应用的上传不受桶级大小限制。
- 真实 Hunyuan I2I 示例任务成功生成 JPEG，私有存储素材记录、task `succeeded` 状态、quota `used +1/reserved -1` 均已核验；测试账号和云端测试数据已清理。
- 修复了 `doc(id).set({data:{_id:id,...}})` 导致 `-501007` 的问题：绑定文档 ID 后不再在 `set` 数据中重复写 `_id`。此前结果文件上传成功但素材登记/事务未提交，修复后任务闭环通过。
- 识花模型尚未开通。当前 `AI_VISION_ENABLED=false`，前后端都会在上传/额度预占前拦截识花任务。
